## 7. シフト自動化 要件

詳細は↓を参照

要件定義_07_シフト自動化

### 最小構成

#### コマ・時間割の登録

- 管理者が1日のコマの区切りを登録する
- 期タイプ（レギュラー／夏期・冬期・春期講習／特別授業）ごとに登録する
- 学年帯（小学生／中学生／高校生）ごとに別の時間帯を登録できる
- コマの名前、開始時刻、終了時刻を保持する
- 学年で時間割を分けない塾は「全学年」だけを登録する
- 高校生は登録が無ければ中学生の枠を使う
- 時刻は "HH:MM" の文字列で保持し、連続・重なりの判定は時刻で行う
- 時間帯が重なるコマがある場合は画面で警告する
- 希望・割当・授業に使われているコマは削除させない
- MVPでは講習期間のコマ割りの初期値を用意しない

#### 塾の予定（カレンダー）の登録

- 管理者が塾の予定を登録する
- 予定の種別は「休校日」と「行事」の2つとする
- 1日だけの予定も、連続した期間の予定も同じ形で登録する
- 開始日・終了日・件名・補足を保持する
- 休校日にはシフト希望を登録させず、自動生成でも割り当てない
- 休校日が後から決まった場合に備え、既に入っている割当を外せるようにする
- 月表示と年間表示を切り替えられる
- 日付を押すとその日の予定を追加でき、予定を押すと内容の確認と削除ができる
- 期（レギュラー／講習期間）が分かるように表示する
- 講師側の画面にも同じ予定を表示する
- MVPでは繰り返し予定（毎週日曜は休校、など）の登録を実装しない
- MVPでは期（講習期間）の登録画面を用意せず、初期データとして持つ

#### 講師の担当科目と勤務上限の登録

- 講師ごとに担当できる科目を登録する
- 講師ごとに1日・1週・連続の上限コマ数と、週の下限コマ数を登録する
- 未設定の講師には既定値を適用する
- 上限は管理者だけが変更でき、講師本人には変更させない
- MVPでは社員・時間講師・学生講師での上限の作り分けを必須としない

#### 科目別の必要人数の登録

- 管理者が日付・コマ・科目・授業形態ごとに必要人数を登録する
- 期の途中でクラスが分割された場合に、その日から必要人数を変えられる
- 曜日単位でまとめて登録し、対象期間へ展開する
- 個別指導は「講師1人が同時にみる生徒の上限」を塾ごとに登録し、必要人数の算出に使う
- 同時に使える集団教室・個別ブースの数を上限として登録する
- MVPでは手入力を基本とし、生徒の受講予定からの自動算出は実装しない

#### シフト希望の登録

- レギュラー期の時間割は**1週間周期のローテーション**で回る
- ローテーションが変わる単位は最小で月、最大で年とし、週単位では変わらない
- 講師へのシフト提出依頼は**期（学期）単位**で行う
- 講師が日付・コマごとに「できれば入りたい／出られる／出られない」を登録する
- 曜日を指定してまとめて登録できる
- 休校日には希望を登録させない
- 管理者が代理入力できる
- 未回答のコマは「出られる」として扱わない
- MVPでは提出締切と締切後のロックを実装しない

#### 管理者用の対象一覧と事前チェック

- 管理者が対象期間を決めてシフト計画を作成する
- 計算に必要な条件が揃っているかを実行前に検証する
- コマ未登録、必要人数未設定、希望未提出、期間がすべて休校日、などの不備を表示する
- 科目ごとに「必要な延べコマ数」と「担当できる講師の出勤可能コマ数」を並べて表示する
- 条件が足りない場合は理由を表示して実行させない

#### 1か月分のシフト自動生成

- 管理者がボタン1つで対象期間の出勤シフトを生成する
- ハード制約 H1〜H14 をサーバー側で検証する
- 「出られない」「未回答」「休校日」「担当外の科目」「上限超過」「同時刻の二重割当」を割り当てない
- 同じ入力なら同じ結果になる
- 講師間の充足率が揃うように割り当てる
- 埋まらなかったコマと理由を表示する
- 貪欲割当のみを実装し、割当後の入れ替え探索は行わない
- 外部の最適化APIやソルバは使わず、自前のアルゴリズムで実装する
- 割当の計算に LLM を使わない（再現性とハード制約の保証ができないため）
- 制約判定はDBに依存しない純粋関数として実装し、自動生成と手動修正の両方から呼ぶ
- 講師50名・1か月分を3秒以内で処理する

#### 結果確認と手動修正

- 講師×コマの盤面で結果を表示する
- 科目別の充足状況を「英 2/3」の形で表示する
- 講師ごとの担当コマ数、充足率、偏りを表示する
- 管理者がマスを押して割当の追加・削除を行える
- 手動修正時もハード制約を検証し、違反する操作は保存しない
- 気に入った割当を固定し、再実行しても残す
- 学年帯・科目で表示を絞り込める
- 自動生成結果をそのまま確定しない

#### 確定と閲覧

- 管理者が確認後にシフトを確定する
- 確定時に「出られない」への割当、休校日への割当、未充足を再確認する
- 確定できるのは管理者だけとする
- 確定前のシフトは講師に表示しない
- 講師には本人の出勤予定だけを表示する
- 確定後に変更する場合は、確定を解除してから修正する
- 確定シフトを iCalendar（ICS）形式で配信し、講師のカレンダーアプリから購読できるようにする
- 購読URLは講師ごとのトークンで本人確認する
- MVPでは確定時の通知を実装しない

### 安全に使うための必須対応

- データベースファイルを git から外す
- 依存パッケージの脆弱性を修正する
- HTTPS を強制する
- ログイン試行回数を制限する
- 初回ログイン時のパスワード変更を強制する
- 講師が他の講師の希望・給与を閲覧できないことを検証する

### 使用技術

#### アプリ基盤

- Next.js 16（App Router、Server Actions）と React 19 で実装する
- TypeScript で記述する
- Tailwind CSS で画面を作る
- 有料ライブラリは使わない（開発者1人あたり年額課金のものが多いため）
- 追加のUIコンポーネントライブラリを入れず、標準のHTMLフォームで作る

#### データベース

- Prisma 7 を ORM に使う
- SQLite（better-sqlite3 アダプタ）で運用する
- SQLite は enum に対応していないため、区分値は文字列と定数で表す
- 日付は "YYYY-MM-DD"、時刻は "HH:MM" の文字列で持ち、タイムゾーン変換を挟まない
- スキーマの変更はマイグレーションとして残す

#### 認証・権限

- 外部の認証サービスを使わない
- パスワードは scrypt でハッシュ化し、1件ごとに異なるソルトを付けて保存する
- セッションは HMAC-SHA256 で署名した Cookie で持つ
- 認可は画面の出し分けではなく、データを読む層で毎回検証する

#### カレンダー

- 塾の予定のカレンダー表示に FullCalendar v7 を使う（MIT ライセンス）
- 月表示（dayGrid）と、日付・予定のクリック操作（interaction）だけを使う
- 有償のプラグイン（リソース表示・タイムライン）は使わない
- 日付の扱いに Temporal を使い、未対応のブラウザ向けに temporal-polyfill を読み込む
- 開閉の状態はURLのクエリで持ち、サーバー側の月表示とライブラリ側の表示のどちらから押しても同じダイアログを開く
- ドラッグによる期間の変更は行わせない（休校日を動かすとシフト希望の可否がその場で変わるため）

#### 外部連携

- 確定シフトの配信に iCalendar（ICS）形式を使う
- 打刻用の二次元コード生成に qrcode を使う

#### 検証

- 検証スクリプトを tsx で実行する
- 制約判定・自動割当・給与計算はDBに依存しない純粋関数として書き、DBを用意せずに検証できるようにする
- ハード制約の境界値と、同じ入力で同じ結果になることを検証スクリプトで固定する

#### AI（試作。MVPには入れない）

- ミーティングのメモから「同じブースに座らせない方がよい生徒の組み合わせ」の候補を抽出する
- ローカルで Ollama を動かし、gemma4:e2b-it-qat（Apache 2.0）を使う
- 追加の依存パッケージを入れず、HTTP で呼び出す
- 出力の形を JSON Schema で固定し、自由文から正規表現で切り出す作りにしない
- 送信前に生徒の実名を仮名ID（「生徒003」）へ置き換える
- 仮名化を通していないテキストは送信しない
- ローカル（Ollama）と外部API（Claude）を差し替えられるインターフェースを挟み、同じテストデータで精度を比較してから本番の構成を決める
- GPU を積んでいないPCでも動かせるよう、対話用ではなく1日1回まとめて処理する使い方を前提にする
- LLM の出力は候補として扱い、管理者が承認したものだけを保存する
