# 7. シフト自動化 要件（概要）

詳細は別ページ「要件定義_07_シフト自動化」を参照。ここは全体像をつかむためのまとめ。

---

## 機能概要

**生徒の予定・講師の入れる日時・講師の教科**の3つをもとに、
**出勤シフトと時間割を自動で作る**機能。

作った案はいきなり確定しない。まず下書きとして保存され、管理者が画面で確認して手直しし、
納得したところで確定する。**確定したものだけが講師に見える。**

### シフトと時間割は分けられない

必要なのは「講師4人」ではなく「**英語2人・数学1人・国語1人**」である。
科目を見ずに人数だけ合わせると、**時間割が組めないシフトができあがる。**
そして「英語が何コマ必要か」は、生徒が何人来るかで決まる。

だからこの機能は、次の3つを1つの流れとして扱う。

| 段階 | やること | 材料 → 結果 |
| --- | --- | --- |
| **段階1** | **必要人数を出す** | 生徒の受講予定 → 「火曜2限は英語が3人必要」 |
| **段階2** | **出勤シフトを作る** | 必要人数 + 講師の希望 + 講師の教科 → 「誰がいつ出て、何を教えるか」 |
| **段階3** | **時間割を作る** | 出勤シフト + 生徒 → 「誰がどの生徒を、どのブースで見るか」 |

### なぜ3段階に分けるのか（1つにまとめない理由）

- **確定するタイミングが違う。** 出勤シフトは早く確定しないと講師が予定を立てられず、給与にも関わる。
  一方、生徒の配置は当日の欠席や振替で動く
- **全部まとめて計算すると、理由が説明できなくなる。**
  忖度をなくすために始めた機能が、別のブラックボックスになっては意味がない
- **段階2までできれば現場は回る。** 時間割が未完成でも、出勤シフトが出れば使い始められる

ただし**段階2で作ったシフトは、段階3が必ず成立する形でなければならない。**
そのため「担当できない科目には割り当てない」を絶対のルールにし、
確定する前に時間割が組めるかを機械的に確かめる。

### 今までとの違い

| | 今まで | これから |
| --- | --- | --- |
| 希望を集める | 紙・チャット・口頭でバラバラ | 講師が自分でアプリに入力 |
| 必要人数 | 組む人の頭の中 | 生徒の受講予定から自動で計算 |
| 「誰が何を教えられるか」 | 組む人の記憶 | 講師ごとに登録され、自動で使われる |
| シフトを組む | 社員が予定を見ながら手で組む | 自動で案を作り、人が手直しする |
| 割当の理由 | 組んだ人の頭の中 | 画面に数字で出る |
| 偏りの確認 | 気づいたら誰かに集中していた | 講師ごとの担当数と差が常に見える |
| 時間割 | シフトが決まった後に手で組む | シフトから続けて自動で作る |

### 特に効かせたいところ

- **シフトを組む人の忖度や贔屓が入る** → 誰にどれだけ割り当てたかを数字で表示し、根拠を残す
- **講習期間に一部の講師へ負担が偏る** → 「偏りを小さくすること」を最優先の目的にする
- **時間割が組めないシフトができてしまう** → 科目まで見て割り当て、確定前に成立を確かめる

### この機能でやること・やらないこと

| | 内容 |
| --- | --- |
| **やる** | 必要人数の算出 → 出勤シフト → 時間割（生徒の配置）まで |
| やらない | 給与計算・打刻。既にある機能で、確定したシフトを受け取って動く |
| やらない | 集団授業のクラス分けそのもの（クラスは決まっている前提で、そこに講師を付ける） |
| 一部だけ | 生徒の相性・騒音。「この2人は同じブースにしない」の登録までは対応し、細かい調整は人が行う |

### 使う流れ

```
【段階1】
管理者  期間と締切を決める
   ↓
管理者  生徒の受講予定を登録する（曜日パターンで入力）
   ↓
システム 「この日のこのコマは、英語が3人・数学が1人」を自動で計算
   ↓
管理者  結果を確認・上書きする（模試の日に増やす等）

【段階2】
講師    締切までに「出られる日」を出す
   ↓
管理者  提出状況を確認（出していない人がわかる）
   ↓
管理者  「シフト自動作成」を押す
   ↓
管理者  結果を見て手直しする（気に入った割当は固定できる）
   ↓
システム 時間割が組めるかを確認   →  組めなければ理由を出して差し戻し
   ↓
管理者  シフトを確定 → 講師のスマホに出勤予定が出る

【段階3】
管理者  「時間割自動作成」を押す
   ↓
システム 出勤する講師に生徒を割り当て、ブースを決める
   ↓
管理者  配置を確認・手直しする
   ↓
管理者  時間割を確定 → 講師に自分の担当授業と生徒が出る
```

## 入力情報

自動作成が材料にするもの。**押すボタンは1つで、その場で人が入力する項目はない。**
必要なものは事前にすべて登録されている状態にする。

### 生徒側（段階1で使う）

- **受講予定** … 誰が、いつ、何の科目を、どの形態（集団／1対1／1対2）で受けるか
  - 曜日パターンで入れる（「田中さんは毎週火曜2限に英語」）
  - 振替・体験・講習の単発受講は日別で追加する
- **同席させたくない生徒の組み合わせ** … 「この2人は同じブースにしない」

### 講師側（段階2で使う）

- **シフト希望** … 時間帯ごとに ◎できれば入りたい / ○出られる / ×出られない
  - 曜日を指定して1か月ぶんまとめて入れられる
- **担当できる科目** … 講師ごとに、教えられる科目と習熟度（可／得意／専門）
  - **これが今回から必須になる。** 全講師について登録しないと自動作成が動かない

### 教室が持っているもの

- 休校日・行事（休校日には希望も割当も入らない）
- 時間帯（コマ）の設定（通常期は夕方3コマ、講習期間は朝から6コマ）
- 講師ごとの勤務上限（1日／1週間／連続の上限、週の最低コマ数）
- 教室・ブースの数と定員

### 大事な決めごと

**回答が無い時間帯には割り当てない。**
「答えていない＝出られる」とは扱わない。黙っていたら勝手に入れられていた、という事故を防ぐため。
その代わり、未提出の講師は警告として名前が出る。

## 出力情報

### 段階1：必要人数

「7/15 の2限は、英語の講師が3人必要」という形。
**なぜ3人なのか（生徒が5人いて1対2だから）も一緒に表示する。**

### 段階2：出勤シフト

「この講師は、この日のこのコマに出勤し、**英語を担当する**」の一覧。
自動で作られたものか、人が手で直したものかを区別して表示する。

### 段階3：時間割

「誰が、どの生徒を、どのブースで、何の科目を見るか」。
**既にある授業の仕組みにそのまま入るので、授業記録・出欠・欠席者カードが自動でつながる。**

### できばえのサマリ

- 必要人数のうち何人ぶん埋まったか（**科目ごとにも出す**）
- 講師ごとの担当コマ数と、「出られると答えたうち何割入ったか」
- **偏り** … 一番多い講師と一番少ない講師の差
- **時間割が組めるかどうか**
- 配置できた生徒数、ブースの使用率

### 埋まらなかったところと、その理由

**理由なしで空欄にはしない。**

| 理由 | 意味 |
| --- | --- |
| 候補がいない | その時間帯に「出られる」と答えた講師が1人もいない |
| **その科目を教えられる人がいない** | 出られる講師はいるが、誰もその科目を担当できない |
| 全員が上限に達している | 候補はいるが、全員その日・その週の上限まで入っている |
| そもそも人が足りない | 必要人数より候補者数が少ない |
| ブースが埋まっている | 生徒を置く場所がない |
| 同席させられない | 「同じブースにしない」組み合わせで置けない |

**「その科目を教えられる人がいない」が今回いちばん重要な表示。**
これが見えないと、現場は「人数は合っているのに、なぜ授業が組めないのか」が分からない。

### 運営上のリスクの警告

- **ある科目を教えられる講師が1人しかいない**（その人が休むと授業が成立しない）
- 担当科目が1件も登録されていない講師がいる

これは割当を止めるものではないが、**採用や研修の判断材料になる**ので表示する。

## 必須条件

### 絶対に破ってはいけないルール

自動作成でも、人が手で直すときでも守る。

**出勤シフト（段階2）**

| | ルール |
| --- | --- |
| 1 | 「出られない（×）」と答えた枠に入れない |
| 2 | 回答が無い枠に入れない |
| 3 | 休校日に入れない（※ **外すのはいつでもできる**） |
| 4 | 同じ人を同じ枠に二重に入れない |
| 5 | 必要な人数より多く入れない |
| 6〜8 | 1日・1週間・連続の上限コマ数を超えない |
| 9 | 辞めた講師を入れない |
| 10 | 「固定」した割当は、やり直しても動かさない |
| 11 | 確定済みのシフトに自動作成をかけない |
| **12** | **担当できない科目に割り当てない** |
| **13** | 同じ人が同じ時間に2つの科目を持たない |

**時間割（段階3）**

| | ルール |
| --- | --- |
| 14 | 同じ講師を同じ時間に2つの教室に置かない |
| 15 | ブースの定員を超えない |
| 16 | 同じ生徒を同じ時間に2つの授業に置かない |
| 17 | 集団授業を個別ブースで開かない |
| 18 | 「同席させない」組み合わせを同じブースに置かない |
| 19 | 出勤が確定していない講師に授業を持たせない |

**12番が今回の設計の要。**
これが無いと、人数だけ合っていて誰も英語を教えられないシフトが「正常」として確定できてしまう。
これがあることで、**シフトが必ず時間割の組める形になる。**

なお 2番と5番だけは、人が手で直すときに限り「警告を出したうえで許可」する。
当日の急な欠員など、自動化が想定しない事態に人が対応できる余地を残すため。

### 動きとして満たすこと

- **同じ条件なら、何度やっても同じ結果になること**
  （やり直すたびに結果が変わると、「やり直せば有利になるのでは」と疑われる）
- **自動作成が失敗しても、手で組めば必ずシフトは完成すること**
- **途中で失敗したら、実行前の状態にきちんと戻ること**
- **なぜその講師が選ばれたのか、画面で説明できること**

### 実行する前に満たしていること

揃っていないと、ボタンを押しても理由を出して止まる。

- 生徒の受講予定・必要人数・シフト希望が登録されている
- 時間帯（コマ）が登録されている
- **必要な科目それぞれについて、担当できる講師が1人以上登録されている**
- 実行する人が管理者である

## 機能要件

### 登録するもの

- 講師が ◎ / ○ / × を月カレンダーから入力できる。曜日でまとめて入れられる
- **管理者が講師ごとの担当科目と習熟度を登録できる**
- **科目ごとに「教えられる講師が何人いるか」を確認できる**（1人しかいない科目を警告）
- **生徒の受講予定を曜日パターンで登録し、期間ぶんまとめて作れる**
- 振替・体験など単発の予定を日別で追加できる
- **「同席させたくない生徒の組み合わせ」を登録できる**
- 提出の締切を設定でき、締切後は講師が編集できない
- 管理者が提出状況を一覧で見られる／代理入力できる

> **同席の考え方について**
> 生徒の相性や騒音は、毎晩のミーティングで口頭で共有されている暗黙知で、
> フォームに書かせようとしても埋まらない。そこで**「この2人は同じブースにしない」という
> 否定形のペア登録だけに絞った。** 思い出したときに1行足せばよい形にする。
> これですべては拾えないが、事故の大半は防げる。残りは手直しで対応する。

### 段階1：必要人数を出す

- 生徒の受講予定から、**日 × コマ × 科目 × 形態**ごとの必要講師数を自動で計算する
  （例：火曜2限に英語を1対2で受ける生徒が5人 → 英語の講師が3人必要）
- 計算結果は管理者が上書きできる（模試の監督枠など）
- **科目ごとに「必要な数」と「その科目を教えられる講師の出勤可能数」を並べて表示する**
  → 「英語は40コマ必要だが、英語を教えられる講師は25コマぶんしか出られない」が
  **自動作成を回す前に分かる。募集やシフト依頼の判断材料になる**

### 段階2：出勤シフトを作る

- ボタン1つで実行できる。条件が足りなければ理由を出して止まる
- 2つのやり方を選べる（**作り直す** / **足りないところだけ埋める**）
- 「偏りをどれくらい重視するか」などの方針を画面で調整してやり直せる
- **確定する前に時間割が組めるかを確認し、組めなければ理由を出して止める**
- いつ・誰が・どんな設定で実行したかを記録する

### 確認して手直しする

- 「講師 × 日 × 時間帯」の表で結果を見られる。色で状態がひと目で分かる
- **セルに担当科目が出る**（「英」「数」など）
- **各コマに「英語は3人必要なうち2人」のような科目別の充足状況が出る**
- クリックで割当を付け外しできる。**気に入った割当は「固定」できる**
- 講師ごとの担当コマ数・充足率・偏りが表示される
- **カーソルを合わせると、なぜその人が選ばれたのかが出る**

### 段階3：時間割を作る

- 確定した出勤シフトと生徒の受講予定から、時間割を自動で作る
- 個別指導では、同じ講師・同じブースに生徒を定員まで詰める
- 配置できなかった生徒を理由付きで一覧表示する
- 管理者が配置を手直しできる（生徒を別のブース・別の講師へ移す）
- 手直しのときもルール14〜19を確認し、違反する操作は拒否する
- 確定すると講師の画面に自分の担当授業と生徒が出る
- 確定後の当日変更（欠席・振替・講師交代）に対応できる

### 確定して共有する

- 「下書き」と「確定」の2つの状態がある。確定できるのは管理者だけ
- **確定前の内容は講師に見せない**
- 埋まらないコマや警告が残っていると、確定時に件数を出して確認を求める
- 確定した後に変えたい場合は、一度「確定を解除」する。誰が・いつ・なぜ解除したかが残る
- 出勤シフトと時間割は別々に確定できる

## 完了条件

**「完成した」と言える基準。すべて自動テストで確認できる形にする。**
「画面を見て問題なさそう」を完了条件にしない。

### ルールを守れているか

- 「出られない」枠・回答が無い枠・休校日への割当が **すべて0件**
- 必要人数を超えたコマが **0件**
- 1日・1週間・連続の上限を超えた講師が **0人**
- **担当できない科目に割り当てられた講師が 0人**
- 固定した割当が、やり直した後も **そのまま残っている**
- 時間割で、定員超過・講師の重複・生徒の重複・同席違反が **すべて0件**

### 自動作成の質

- **同じ条件で10回実行して、10回とも同じ結果になる**（シフト・時間割とも）
- 講師どうしの担当コマ数の差が **2コマ以内**に収まる
- シフトは講師50人・1か月ぶんで **3秒以内**、時間割は生徒300人で **5秒以内**
- ◎を出した講師が○だけの講師より優先される
- **その科目が得意・専門の講師が優先される**
- **「人は足りているが、その科目を教えられる人がいない」を正しく見分けられる**
- **「英数ができるAさんが数学に入っていて英語が空いている。数学はBさんでも代われる」
  という状況で、自動で入れ替えて英語を埋められる**

### いちばん重要な確認

- **自動で作ったシフトを時間割にかけると、必ず全員が配置できること**
- **科目が足りないシフトは、確定しようとすると止まること**

段階を2つに分けた設計が正しかったかは、この2つで決まる。

### 業務の流れが通るか

- 受講予定の登録 → 必要人数の計算 → シフト作成 → 時間割作成 → 確定 が**通しで完了する**
- 締切を過ぎた後に講師が希望を変えようとすると、きちんと止まる
- **確定前のシフトが、講師の画面に一切出ていない**
- 確定後に、講師の画面に自分の出勤と担当授業が出る
- 講師が他の講師の希望を見ようとしても、見られない
- **自動作成を一度も使わず、手だけでシフトを完成・確定できる**
- 作った時間割の上で、**既にある授業記録・出欠入力・欠席者カードがそのまま動く**

### 引き渡しのとき

- 動作確認用のデータで、**「埋まらない」「偏っている」といった問題が実際に画面に出る**こと
  （うまくいく例だけでなく、問題が見える状態も再現できるようにする）
- 使い方と考え方を README に書く

## 未決定事項

### 開発を始める前に決めたいこと

| | 決めること | 論点 |
| --- | --- | --- |
| 1 | ★★ **生徒の受講予定はどこから来るか** | **この機能全体の起点。** 塾HR に新しく入力するのか、既存のシステム（LuBo School など）に既にあるのか。**あるなら二重入力させてはいけない**ので、取り込み方を先に決める |
| 2 | ★ **集団のクラス分け** | 今回は「クラスは既に決まっている」前提にした。クラス分け自体も自動化したいか |
| 3 | ★ **担当科目を誰が登録するか** | 全講師 × 全科目の登録が必要になる。「可／得意／専門」の判断基準を誰が決めるか |
| 4 | ★ **勤務上限の数字** | 「1日4コマ・週12コマ・連続3コマ」は仮置き。学生と社員で分けるか。労働時間のルールとの兼ね合い |
| 5 | ★ **回答が無い枠の扱い** | 今回は「入れない」とした。現場が「未回答＝出られる」で運用していないか要確認 |
| 6 | ★ **提出の締切** | 何日前までか。締切後の変更をどこまで認めるか |
| 7 | ★ **路線チームとデータを共有するか** | 講師の名簿や日付の形式を両機能で共有するなら、設計を先に合わせる必要がある |

### 進めながら決めればいいこと

- 公平とは何か（「出られると答えたうち何割入れたか」を揃えるようにしたが、
  現場は「単純なコマ数」を揃えたいと思っていないか）
- 社員と学生講師で扱いを変えるか
- 「同じ生徒は同じ講師が見続ける」を優先するか
- **同席させないペアの登録だけで、現場の暗黙知が拾えるか**（実際に運用して確かめる）
- 複数の校舎に対応するか（今回はひとまず1校舎で作る）
- 確定したシフト・時間割を生徒・保護者にも見せるか
- 当日の欠員が出たときの代打募集をアプリでやるか
- 使う技術・本番環境・ログイン方式（全体の第11章と共通）

### 今回こちらで仮に決めたこと

実装は進められるが、現場に確認して変わる可能性があるもの。

- 回答が無い枠には割り当てない
- 勤務上限は 1日4コマ / 週12コマ / 連続3コマ
- 偏りは「4コマ以上の差」で警告、「2コマ以内」を目標とする
- 最適な答えを探すより、**説明できて結果が安定していること**を優先する
  （毎月まったく違うシフトが出て現場が混乱するのを避けるため）
- **シフトと時間割を3段階に分け、それぞれ別に確定する**
  （これは設計の根幹なので、変えるなら全体をやり直すことになる）
- 集団のクラス編成は決まっているものとして扱う
- 生徒の相性は「同席させないペア」の登録だけで表現する
- まずは1校舎で作る

## 途中まで作った段階で何が使えるか

全部できないと使えない、という作り方にはしない。

| どこまで | 現場で使えるもの |
| --- | --- |
| 必要人数の計算まで | 「どの科目が何コマ必要か」が見える。手作業のシフト組みの下敷きになる |
| **出勤シフトまで** | **ここで実運用に入れる。** 時間割は従来どおり手作業 |
| 時間割まで | 授業記録・欠席者カードまで自動でつながる |
