## 2. 日付ごとのやりとり（チャット）

**背景** — シフトの相談が口頭や個人LINEに逃げていた。`ShiftRequest.note` の一言欄では
返事ができず、言った言わないになる。

**作ったもの**

- `ShiftComment`（マイグレーション `20260808095910_add_shift_comments`）
- `lib/comments.ts` … スレッド取得・未読集計・既読処理
- `app/comments/actions.ts` … 投稿。`app/components/ChatBox.tsx` … 吹き出しUI

**決めたこと**

- **スレッドは「講師 × 日付」で1本。** 提出カレンダーと確定カレンダーは別画面だが、
  同じ日の話なので同じスレッドを開く。分けると両方を見に行くことになり、片方が見落とされる
- **既読になるのは、利用者が自分で日付を開いたときだけ。** 既定表示のまま既読にすると、
  本人が見ていないのに未読が消える
- **`ShiftRequest.note` / `ShiftAssignment.note` は画面から外した**（カラムは残置）
- 新着は15秒間隔の取り直し。**常時接続ではないので数秒の遅れが出る。**
  スマホのプッシュ通知（アプリを閉じていても鳴る）は未対応で、PWA + Web Push が要る

**開ける場所** — 講師の提出画面・確定画面・管理者の `/shifts`。未読は3箇所に出す
（日付のマス／講師タブ／管理者の講師切り替えボタン）。

## 3. 講師画面の分割

`/t`（提出）と `/t/schedule`（確定シフト・時間割）を**別のカレンダー**に分けた。
片方は「希望を入れる場所」、もう片方は「決まったことを見る場所」で、重ねると
今どちらを見ているのか分からなくなるため。下タブは5つになった。

`/t` から確定シフトの重ね表示（`●2`・「出勤確定」バッジ）は撤去した。

**確定前を見せない仕組み**は自前で作らず、別セッションの `ShiftPlan.status`
（DRAFT / CONFIRMED）に繋いだ。ゲートを二重に作るとどちらが効いているか分からなくなる。
手で入れた割当（`planId` が null）は従来どおり見える。

## 4. カレンダー購読（.ics）

**講師が普段使っているカレンダーアプリで確定シフトを見られるようにした。**

- `app/api/ics/[token]/route.ts` … `Teacher.icsToken` が本人確認そのもの
- `lib/ics.ts`（純粋関数）＋ `lib/ics-feed.ts`（DB）
- `/t/schedule` に購読URL・コピー・再発行ボタンと、アプリ別の手順

**決めたこと**

- **コマ単位で1件にまとめる。** 出勤と授業を別の予定にすると同じ時間帯に2件並ぶ
- **UID は「日付-コマ」**。割当行が作り直されても重複しない
- **時刻は UTC 固定変換**（日本にサマータイムが無いので9時間引けば必ず正しい）。
  `VTIMEZONE` を持たせるより読み手側の対応差が出ない
- **生徒は「生徒039」形式の仮名**。`lib/ai/anonymize.ts` の `pseudonym()` を流用。
  実測で実名の出現0件・仮名6件
- **検討中の割当は流さない。** 私物のカレンダーに出したら取り消せない

**アプリ別の対応**（`競合比較_ComiruHR.md` にも記載）

| | 購読URLの直接登録 |
| --- | --- |
| Google カレンダー | ○（反映は数時間〜1日遅れ。Google側の仕様） |
| iOS標準カレンダー | ○（Googleより速い） |
| TimeTree / Lifebear | **✕**。Googleか端末カレンダーを経由する |

- 送信済みかは**件名で照合**（`payslipNoticeSentAt`）。通知フラグ用のテーブルは作らない。
  連絡そのものが記録なので、2箇所に持つと必ず食い違う

## 6. 賃金項目マスタ ← **未完了あり**

**背景** — ComiruHR の事例（PDF p15）に「コマ給が20や30なんてこともあります」とある。
塾HR は講師×授業形態の3種類しか持てなかった。

**作ったもの**（マイグレーション `20260809132141_add_pay_items`）

- `PayItem` … 管理者が作る賃金項目。名前・計算方法・並び順
- `TeacherPayRate` … 講師×項目の単価
- `/payroll/items` … 項目の追加・変更・削除
- `/payroll/settings` … 列が項目の数だけ自動で増える
- `lib/payroll.ts` の計算を項目ベースに全面書き換え

| 計算方法 | 数量の出どころ |
| --- | --- |
| コマ数 × 単価 | 勤怠でコマを記録するときに項目を選ぶ |
| 時間 × 単価 | 記録した作業時間（端数は月合計から1回だけ四捨五入） |
| 出勤日数 × 単価 | 出勤日。通常期／講習期間で分けられる |
| 月額固定 | 単価を入れた講師に毎月そのまま付く |

**決めたこと**

- **授業形態（`Lesson.format` / `ShiftAssignment.format`）は触っていない。**
  あちらは「どう教えるか」で部屋の定員や自動配当が使う概念、賃金項目は「いくら払うか」。
  分けたことで**別セッションの自動配当と衝突しない**
- **空欄は0円ではなく「未設定」。** 未設定の項目に実績があると画面で警告を出す
- **使われている項目は削除せず「使わない」に切り替える。** 消すと過去の明細の金額が変わる
- 移行時に、それまでの `WageRate`・時給・交通費はすべて項目として作り直した

### ⚠️ まだ終わっていないこと

> **勤怠画面（`/attendance`）で賃金項目を選べない。**
>
> 今は旧来どおり授業形態を記録し、そこから項目を引く仕組み（`PayItem.legacyStyle`）で
> 動いている。そのため**「模試監督」のような新しい項目は、画面から記録できない。**
> ここを入れて初めて20〜30種類が実運用に乗る。**次にやるならここ。**

あわせて、`Teacher.hourlyWage` / `commuteRegular` / `commuteSpot` / `WageRate` は
**移行元として残したまま未使用**。落ち着いたら削除するか要相談。

## 7. カレンダーの作り替え（Schedule-X）

**導入したもの** — `@schedule-x/react` 4.1.0 / `@schedule-x/calendar` 4.6.1 /
`@schedule-x/theme-default` 4.6.1。**すべて MIT、費用0円。**
peer の `preact` / `@preact/signals` / `temporal-polyfill` も MIT。
`docs/ライブラリのライセンスと費用` のチェックリストで確認済み。

**コスト実測** — JS 124KB（gzip 66KB）＋ CSS 12KB（gzip 5KB）。`?view=sx` を開いたときだけ読む。

**置いた場所** — `/calendar`（塾の予定）の3つ目のタブ「新カレンダー」のみ。
既定は今までの月表示のまま。Schedule-X を import しているのは `SxCalendar.tsx` の1ファイルだけで、
消せば依存ごと外れる。

### つまずいた点（同じ轍を踏まないために）

1. **v4 から日付が `Temporal`** になっている。ネット上の記事はほぼ v2〜v3 で文字列。
   `temporal-polyfill/global` をライブラリより先に読み込む必要がある
2. **日付クリックが効かなかった。** 幅700px未満だと Schedule-X が月グリッドを諦めて
   アジェンダ表示に自動で切り替わり、そちらは `onClickDate` ではなく
   **`onClickAgendaDate`** を使う。両方に繋いで解決
3. **予定が点にしか見えなかった。** 同じ自動切り替えが原因。`isResponsive: false` で止めた
4. **カレンダーは一度しか組み立てられない。** 月送りは `key` で作り直させている

### 今の状態

- 日付のマスを押す → その日の予定を**追加**するダイアログ
- 予定を押す → 中身と**削除**のダイアログ（休校日には警告付き）
- 上記は**月表示・年間表示・新カレンダーの3つすべて**で動く
- 見た目は Google カレンダー風（`google-like.css`）。薄い罫線・108pxの行・
  今日は青い丸・角丸の色付きピル。**ロゴや商標は使っていない**

**→ 見た目の最終確認が未完。** 気になる箇所があれば `google-like.css` 1ファイルで直せる。
