# 競合比較：ComiruHR と 塾HR

塾HR が何を作り、何を作らないかを決めるための、ComiruHR との突き合わせ。

出典は POPER 社のサービス資料 `ComiruHR_service_16p_250512.pdf`（2025年5月版・全16ページ）。
**この資料は、既存の要件定義がもとにしたものと同じ。**
`prisma/schema.prisma` の `WageRate` にある「PDF の事例『同じ講師でも指導内容で時給が変わる』」
というコメントは、本資料 p15 の東大セミナーの事例を指している。

---

## 1. 結論

| | |
| --- | --- |
| **ComiruHR の正式リリース済み機能** | シフト管理・勤怠管理・給与管理の**3つだけ** |
| 講師連絡・二次元コード打刻 | **ComiruHR ではなく Comiru BASIC 側**の機能（p7, p9） |
| **塾HR の充足状況** | 上記3機能＋連絡＋打刻を**すでに網羅している** |
| 塾HR に無いもの | 生徒の出席可能日との自動マッチング（別途開発中） |
| ComiruHR にも無いもの | 講師情報管理・採用管理・有給管理（すべて Coming Soon、p10） |
| **今回のスコープ** | Coming Soon の3つは**入れない**（第5節） |

**塾HR は ComiruHR と Comiru BASIC の一部を、1つのアプリにまとめた形**になっている。

---

## 2. ComiruHR の中身（p5〜p9）

資料が「4つの特長」として挙げているもの。

### 2-1. シフト管理（p6）

- 講師はスマホでコマ単位のシフトを提出
- 提出 → 調整 → 確定 → 連絡 までを効率化
- 回収したシフト希望をもとに座席を組める
- **生徒の出席可能日を Comiru 上で回収することで、自動マッチングが可能**

### 2-2. 勤怠管理（p7）

- 学習塾特有の勤務形態に特化。**担当コマ・事務作業・1日複数回の入退室**
- **専用端末不要**。二次元コード読み取りで入退室を記録（生徒と同じ端末を使える）
- シフトベースの勤怠把握
- ※「講師の入退室管理は Comiru でご利用頂くことが可能です」と明記されている

### 2-3. 給与管理（p8）

- コマ給・時間給に対応
- 勤怠実績からボタン一つで給与計算＆明細発行
- 講師はスマホで給与明細を確認できる
- **定期のある期間と、定期のない講習期間とで交通費を別に登録し自動計算**

### 2-4. 講師連絡（p9）

- 一斉連絡・個別連絡。プライベートの連絡先を交換せずに済む
- **既読／未読が分かる**
- アンケート機能
- ※「本機能は Comiru でご利用頂くことが可能です」と明記されている

## 4. 機能の突き合わせ

| ComiruHR の機能 | 塾HR | 実装箇所 |
| --- | --- | --- |
| スマホでコマ単位のシフト提出 | ✅ | `/t`、`ShiftRequest` |
| 提出・調整・確定・連絡 | ✅ | `/shifts`、`ShiftAssignment`、日付ごとのやりとり（`ShiftComment`） |
| 確定前と確定後を区別する | ✅ | `ShiftPlan.status`（DRAFT / CONFIRMED） |
| 担当コマ・事務作業・1日複数回の入退室 | ✅ | `DutyRecord` / `AdminWork` / `Punch` |
| 専用端末不要の二次元コード打刻 | ✅ | `punchToken`、`/p/[token]`、`/attendance/kiosk` |
| シフトベースの勤怠把握 | ✅ | 確定シフトを実績に写せる（`verify-payroll` [11]） |
| コマ給・時間給 | ✅ | `WageRate`（講師×授業形態） |
| ボタン一つで給与計算＆明細発行 | ✅ | `/payroll` |
| 講師はスマホで給与明細を確認 | ✅ | `/t/payslip` |
| 定期あり／なしで交通費を別計算 | ✅ | `Teacher.commuteRegular` / `commuteSpot` |
| 一斉連絡・個別連絡 | ✅ | `Message` / `MessageRecipient` |
| 既読／未読 | ✅ | `MessageRecipient.readAt` |
| アンケート | ✅ | `MESSAGE_KIND.SURVEY` |
| 生徒の出席可能日との自動マッチング | ⏳ | 開発中（`ShiftPlan` / `ShiftDemand`） |

**塾HR にあって ComiruHR に見当たらないもの**

- 欠席者カード（`AbsenceCard`）— 欠席した生徒に渡す紙の控え
- 確定シフトのカレンダー購読配信（`/api/ics/[token]`）— Googleカレンダー等に流し込む
- 日付ごとの1対1のやりとり（`ShiftComment`）— ComiruHR の講師連絡はお知らせ型

## 5. 今回のスコープに入れないもの

**ComiruHR 側でも Coming Soon（p10）の3つは、現段階では作らない。**

| | ComiruHR の説明 | 判断 |
| --- | --- | --- |
| 講師情報の管理 | 個人情報や指導可能科目などの教務情報。休退職した講師の情報管理 | **今回やらない**（指導可能科目 `TeacherSubject` のみ実装済み） |
| 採用管理 | 採用時の必要書類記入をシステム上で行いペーパーレス化 | **今回やらない** |
| 有給管理 | 有給日数や申請承認管理。非常勤の複雑な有給日数計算 | **今回やらない** |

**やらない理由** — 競合にも無い領域であり、差別化の余地はあるが、
今の開発段階では中核機能（シフト・勤怠・給与・連絡）を固める方が先。
必要になった時点で改めて検討する。

**将来やるなら有給管理から。** 非常勤の比例付与には法定の計算式があり、
年5日の取得義務もあるため、実務上の必要性が最も高い。

## 6. 残っている検討事項

Coming Soon とは別に、資料を読んで出てきた論点が2つある。

### 6-1. 給与明細が出たことを講師に知らせていない → 対応済み（2026-08-09）

導入事例（p14）で、**「給与明細が本部から講師のスマホに通知されるというのは
当塾にとっては劇的な変化でした」**と評価されている。

塾HR は `/t/payslip` で明細を見られるが、**出たことを知らせる仕組みが無かった。**

**対応** — `/payroll` に「講師に知らせる」ボタンを追加。押すと既存の連絡機能（`Message`）に
1件作られ、講師側に未読が付く。

- 送り先は**支給が発生した人だけ**。0円の人に「明細ができました」は届けても意味がない
- **金額は本文に入れない。** 連絡は1件を複数人で共有する作りなので、本文に金額を書くと
  全員に同じ額が出てしまう。金額は各自の明細画面で見てもらう
- 送信済みかどうかは件名で照合する（`payslipNoticeSentAt`）。通知フラグ用のテーブルは
  作っていない。連絡そのものが記録なので、同じことを2箇所に持つと必ず食い違う
- 送り直しは可能。あとから入った講師や、金額を直したときに要るため（確認ダイアログ付き）

### 6-2. コマ給の種類数が足りるか → 対応済み（2026-08-09）

事例（p15）に**「コマ給が20や30なんてこともあります」**という記述がある。
塾HR の `WageRate` は**講師×授業形態の3種類（集団／個別1対1／個別1対2）しか持てない。**

ただし同じ事例は、

> ComiruHR 導入後はなるべくシンプルに給与計算できるように改善していきました。
> 自社の都合に合わせてシステムをどんどんカスタマイズするのではなく、
> 会社の仕組みを一般的な考えに合わせていく。

とも述べており、**製品側も単純化を促す方針**である。塾HR の3種類はこの考え方に沿っている。

**対応** — 給与の項目そのものを管理者が作れるようにした（`PayItem`）。
名前も数も教室が自由に決められるので、コマ給が20でも30でも表せる。

| 計算方法 | 数量の出どころ |
| --- | --- |
| コマ数 × 単価 | 勤怠でコマを記録するときに項目を選ぶ |
| 時間 × 単価 | 事務作業などの記録時間（端数は月合計から1回だけ四捨五入） |
| 出勤日数 × 単価 | 出勤日。通常期（定期あり）と講習期間（定期なし）で分けられる |
| 月額固定 | 単価を入れた講師に毎月そのまま付く |

**授業形態（`Lesson.format` / `ShiftAssignment.format`）は変えていない。**
あちらは「どう教えるか」で部屋の定員や自動配当が使う概念、賃金項目は「いくら払うか」。
同じ1対2でも講師の等級で単価を変えたい、逆に授業ではない監督業務にもコマ給を付けたい、
という要求はどちらか一方では表せない。分けたことで、開発中の自動配当とも衝突しない。

単価は `TeacherPayRate`（講師×項目）で持つ。空欄は0円ではなく「未設定」で、
未設定の項目に実績があると給与計算の画面で警告が出る（設定漏れと「働いていない」を
区別するため）。移行時に、それまでの `WageRate`・時給・交通費はすべて項目として作り直した。
